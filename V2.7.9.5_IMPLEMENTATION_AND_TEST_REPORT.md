# IRD Assistant v2.7.9.5 — Implementation & Test Report

## Scope
This release is an additive update to the v2.7.9.4 Android-style IRD Assistant baseline. It contains three workstreams:

1. WIB timestamp correction using the Apps Script server clock as the authoritative source.
2. In-app Task Completed notifications broadcast to all clients using the same Apps Script URL and Spreadsheet ID. No recipient configuration is added.
3. Task Reply / Discussion for Order Takers and Staff on live and completed tasks.

## Timestamp handling
- Apps Script creates Start and Completed timestamps.
- Timestamp fields are stored/read as absolute instants; UI labels are formatted with `Asia/Jakarta`.
- Due Date/Time are treated as Jakarta wall-clock fields and parsed with an explicit `+07:00` offset.
- Frontend estimates server-clock offset using request/response midpoint and applies it to countdowns, default due time, and day rollover.
- Apps Script sets the target spreadsheet timezone to `Asia/Jakarta` when handling API requests.
- Existing history values are not mass-shifted because their intended original time cannot be inferred reliably.

## Internal notifications
- Completion creates one `TASK_COMPLETED` record keyed by Task ID.
- Every app client using the same shared backend reads the same feed.
- No WhatsApp, Telegram, or recipients Settings page is used.
- Read state is separate by configured Staff Name. If Staff Name is not configured, a stable browser/device identity is used.
- Feed stores the latest records in `IRD NOTIFICATIONS`; read status is stored in `IRD NOTIFICATION READS`.
- The app's persistent feed synchronizes while the app is open and polling. Browser/OS notifications are best-effort and depend on permission. This release does not guarantee delivery while the browser is closed.

## Task Reply / Discussion
- Reply controls are added to live Task cards and Completed cards.
- Both Order Takers and Staff can post/read replies; no role-based restriction is imposed by the frontend.
- Messages are linked to Request ID in `TASK DISCUSSION` and remain after completion.
- Reply messages do not generate a global broadcast notification; global notification scope remains Task Completed only.

## Additive storage
New sheets are created automatically when the backend is called:
- `IRD NOTIFICATIONS`
- `IRD NOTIFICATION READS`
- `TASK DISCUSSION`

Existing task/history columns are not shifted; missing metadata headers are appended by name.

## Not verified from this environment
- Live Apps Script deployment/authorization and writes to the user's real Spreadsheet/Drive.
- User's deployed Vercel project and actual domain configuration.
- Multi-device delivery against the user's production devices.
- Full interactive browser testing in a hosted browser; the available browser sandbox blocked navigation to the local test server.

## Deployment — both sides are required
1. In the existing Apps Script project, replace `Code.gs` with the file in this package under `IRD_Assistant_Guest_Request_Tracker_v2.7.9.4_ANDROID_STYLE_TASKS/google-apps-script/Code.gs`.
2. Save and deploy a **new Web App version** on the existing deployment. Keep the existing `/exec` URL and current access/execute-as settings.
3. Deploy the complete frontend package contents to the **same Vercel project and Root Directory**. `index.html`, `assistant.js`, `assistant.css`, `manifest.json`, `service-worker.js`, `api/`, and assets must keep their relative paths.
4. Keep the same Spreadsheet ID and sheet names. The three feature sheets are created automatically.
5. Hard-refresh the site or clear the installed PWA's site data only if the new asset version still does not load. Do not delete the shared Google Sheets data.

## Acceptance checklist
- Compare a new task's Created Time with a trusted WIB clock.
- Check its Due Time and countdown immediately after saving.
- Complete it and compare Completed Time and Duration.
- Confirm `Asia/Jakarta` on the spreadsheet and Apps Script project.
- Complete a task and verify a notification appears on a second client using the same backend.
- Read notification on one configured Staff Name and verify another Staff Name remains unread.
- Reply from Order Taker, then read/respond as Staff on another client.
- Confirm the same discussion remains accessible from the Completed card.

## Known limitations
- The current app uses configured Staff Name as notification reader identity; there is no separate secure user-account login. Each person should have a distinct Staff Name on their own Settings configuration for per-person read state.
- Existing historic timestamps and pre-existing due timestamps are not automatically shifted. Old values may have been written under a previous clock/timezone configuration; correct them only after checking the actual source values.
- Native OS notifications require permission and the app to be open/polling in this release. Persistent in-app notifications are available when the app reconnects.
